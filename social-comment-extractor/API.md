## 1. ตี sentiment — `POST /classify`

```jsonc
// ขอ
{ "texts": ["คอมเมนต์ 1", "คอมเมนต์ 2"],   // ≤ 50 ใบต่อคำขอ (CLASSIFY_MAX)
  "model": "claude-opus-5",                 // ไม่ใส่ = ใช้ค่าที่ตั้งไว้ที่ Cloudflare
  "effort": "low",                          // ไม่ใส่ = คิดเต็มที่ · haiku ไม่รองรับ (ระบบกันให้แล้ว)
  "context": "โพสข่าวปลาหมอคางดำ" }         // ไม่บังคับ — ช่วยให้ตีแม่นขึ้นมาก

// ตอบ
{ "ok": true, "ver": 34, "rubric": "v6", "model": "claude-opus-5",
  "missing": 0,                             // จำนวนใบที่โมเดลไม่ตอบ — ต้องเช็คทุกครั้ง
  "results": [ { "sentiment_cp": "Neutral", "overall_cred": "Negative", "is_sarcasm": 0 } ],
  "tokens": { "input": 1234, "output": 567 } }
```

**ได้ 2 แกนพร้อมกันในการยิงครั้งเดียว — ไม่ได้จ่าย 2 เท่า**

| แกน | ตอบคำถาม | เหมาะกับ |
|---|---|---|
| `sentiment_cp` | มองแบรนด์ CP ยังไง (ด่ารัฐ = กลาง) | หน้า `/issue/sentiment` |
| `overall_cred` | **โทนรวม (ด่ารัฐ = ลบ)** | ✅ **news feed น่าจะใช้อันนี้** |
| `is_sarcasm` | ธงประชด — กำกับเฉยๆ ไม่เปลี่ยนป้าย | |

> 🔴 **ต้องเคาะก่อนเขียนโค้ดว่าใช้แกนไหน** แล้วเขียนกำกับบนหน้าเว็บ
> ถ้า 2 หน้าใช้คนละแกนแล้วไม่บอก คนจะเอา % มาเทียบกันแล้วสรุปผิด
>
> ⚠️ **`missing > 0` = โมเดลไม่ตอบบางใบ ห้ามเติมค่าเอง** ("ไม่รู้ ≠ กลาง")
> ต้องแยกไว้แล้วบอกผู้ใช้ — บทเรียนที่แพงที่สุดของโปรเจกต์นี้อยู่ใน `CLAUDE.md` หัวข้อ 🧠 ข้อ 4

## 2. 🧠 ระบบเรียนรู้ — `POST /feedback`

**นี่คือส่วนที่ทำให้ "tool เรียนรู้ได้"** · ทำงาน 3 ชั้น (รายละเอียดเต็มใน `FEEDBACK.md`)

```
① ผู้ใช้กดแก้ป้ายบนหน้าเว็บ    → แก้รายงานใบนั้นทันที ไม่ยิงหลังบ้าน
② POST /feedback              → เข้ากองรอตรวจ · ⚠️ ยังไม่มีผลกับใคร
③ เอากองมาวัดกับชุดเฉลย 475 ใบ → ผ่านเกณฑ์แล้วคนเขียนเป็นกฎในโค้ด
```

```jsonc
{ "items": [{
    "text": "ขอบคุณที่ดูแลผืนป่าให้พวกเรา",  // ≤ 400 ตัวอักษร
    "was": "neutral",      // ป้ายก่อนแก้ (ที่แสดงอยู่บนจอ)
    "now": "positive",     // ป้ายที่ผู้ใช้แก้เป็น
    "target": "overall",   // แก้แกนไหน: "cp" | "overall"
    "from": "neutral",     // 🏷 ป้ายเดิมจาก Zocial  ← เพิ่มให้ห้องใหม่โดยเฉพาะ (v34)
    "src": "zocial",       // 🏷 แก้มาจากชั้นไหน: "zocial" | "ai"
    "model": "zocial", "ver": 34, "rubric": "v6"
  }] }                                        // ≤ 60 ใบต่อคำขอ
```

**`from` + `src` คือช่องที่เพิ่มให้ตอบโจทย์ "จำ pattern ที่ Zocial ผิด"** (worker v34)
ไม่มี 2 ช่องนี้ = รู้แค่ว่าผิด แต่ไม่รู้ว่า **ต้นทางผิดแบบไหน** ซึ่งเป็นข้อมูลที่เอาไป
คัดกรองได้ว่าใบไหนต้องส่งให้ AI ตรวจซ้ำ → **ประหยัดเงินโดยตรง**

> 🚫 **ห้ามส่งชื่อผู้คอมเมนต์ · ลิงก์โพส · เวลาแบบละเอียด** — เก็บแค่ข้อความกับป้าย
>    (`PRIVACY_NOTE.md` ข้อ 4.1) · ระบบตัดค่าที่ไม่รู้จักทิ้งให้อยู่แล้ว แต่อย่าส่งมาแต่แรก
> 🚫 **ห้ามส่งอัตโนมัติตอนผู้ใช้กดแก้ป้าย** — ต้องให้ผู้ใช้กดปุ่มส่งเอง
>    (แก้ทีละใบ 10 ใบ = ยิง 10 ครั้ง) · หน้า `/issue/sentiment.html` ทำแบบนี้อยู่ ดูเป็นตัวอย่างได้
> 🚫 **ของในกองไม่มีผลกับ AI จนกว่าจะผ่านการวัด** — เป็นกฎที่เจ้าของสั่งไว้ชัด
>    ห้ามเขียนโค้ดให้กองไปสอน AI เอง ไม่ว่ากรณีใด

**อ่านกอง** — `GET /feedback?key=<FEEDBACK_KEY>` (ต้องมีกุญแจเสมอ · ไม่ตั้ง = ปิด)
มีหน้าอ่านให้แล้วที่ `/issue/sentiment-eval.html` (กล่อง "กองรอตรวจ")
